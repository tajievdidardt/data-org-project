# CLAUDE.md — контекст проекта «Организация данных» (ВШМ СПбГУ)

Ты помогаешь одному из 4 участников группового проекта. Части связаны: твоя работа обязана стыковаться с остальными через общие ID в `00_brief/interfaces.md`. Спроси пользователя, какая часть его (P1–P4), если это не ясно из контекста.

## Проект
Курсовой проект по дисциплине «Организация данных» (занятия 1–8): спроектировать решение по организации данных для бизнес-кейса — от бизнес-проблемы до архитектуры, управления и рисков.
- Кейс (компания, проблема, цифры): `00_brief/case.md` — единственный источник правды.
- Критерии сдачи: `00_brief/requirements.md`. Если раздел «Официальные» ещё TODO — один раз напомни, что критерии не сверены со слайдами 4–7.

## Кто что делает
| Часть | Папка | Содержание | Доп. роль |
|---|---|---|---|
| P1 | `part1_problem-logic` | DECISION, SMART-цели, логическая модель | интегратор финала |
| P2 | `part2_sources-model` | источники ERP/CRM/Open Data, типы данных, 5V, модель данных, формулы метрик | владелец ID S#/E# |
| P3 | `part3_architecture-pipeline` | ETL/ELT, Raw→Staging→Target→DWH→Marts, жизненный цикл, FAIR | итоговая схема архитектуры |
| P4 | `part4_governance-risks` | DAMA-DMBOK, роли, качество и безопасность, Data Culture, ISO 31000 | QA по requirements.md |

## Сквозная логика (главное, что делает работу цельной)
Проблема (P1) → SMART-цели с метриками **M#** (P1) → каждая M# считается из сущностей **E#** и источников **S#** (P2) → проходит через пайплайн в витрины **D#** (P3) → у каждой есть владелец, правило качества и риски **R#** (P4).
- Все ID живут в `00_brief/interfaces.md`. Новый ID — добавь строку в свою секцию; в чужих секциях только дописывай колонки, отведённые твоей части.
- В черновиках ссылайся на ID («M2 считается из E1+E3»), а не пересказывай чужие части.
- Любая M# без пути до D# и R# — дыра; скажи об этом пользователю.

## Экономия токенов
1. Читай только: `00_brief/case.md`, `00_brief/interfaces.md`, свой `TASK.md` и свой `draft.md`. Чужие папки — только для задачи на стыковку.
2. `knowledge/course-kb.md` целиком не читай: открывай только разделы, указанные в твоём TASK.md (ищи по заголовку `## N.`).
3. Правь точечно, не переписывай файлы целиком.
4. Сначала тезисы и логика, оформление — один раз в конце.
5. Отвечай кратко, не пересказывай то, что уже лежит в файлах.

## Качество
- Помечай: **[факт: источник]** / **[допущение]** / **[вывод]**. Цифры без источника — только как допущение.
- Открытые данные (data.gov.ru, Росстат, data.europa.eu) и нормы (например, 152-ФЗ) — проверяй поиском, давай ссылку.
- Фреймворки курса применяй к кейсу, а не пересказывай теорию: на каждый — «как это выглядит у нашей компании и что мы делаем».
- Терминология — как в `knowledge/course-kb.md`.
- Нужно изменить общий факт (кейс, чужой ID) — не правь сам: запиши предложение в `00_brief/decisions.md` и скажи пользователю.
